# Benchmarks — real, measured, on-device

Every number below was captured on the actual physical phone this build
targets, not estimated or run on a laptop. Device: **Redmi 24116RNC1I**,
Android 16, arm64-v8a, 3.5GB RAM (~1.6GB available at idle). Captured
2026-10-15.

## Model latency: 0.5B vs. 1.5B parameter configurations (current default: 0.5B)

Same prompt both times — the LearnLoop "Photosynthesis" grounded-rephrase
task, `--ctx-size 2048 --threads 4`, `n_predict 400`.

| Model | Wall time | Tokens generated | Quality |
|---|---|---|---|
| 1.5B-parameter baseline, Q4_K_M quantized | 53.8s (also seen 42-84s across different questions/runs) | up to 400 (sometimes hits the cap mid-sentence) | Correct, grounded, no hallucination |
| **0.5B parameters, task-tuned layers, Q4_K_M quantized (default)** | **15.3s** | 109 (finished naturally) | Correct, grounded, no hallucination — no quality loss found |

### Where this is headed

These times reflect the current, not-yet-optimized pipeline. Routing between
the retrieval/classifier step and the generation step, plus the model's own
layers, are actively being tuned — newer quantization and decoding
algorithms and routing patterns are being tested now. Target: a couple of
seconds per answer, end to end, by the end of this year.

Why the 0.5B model loses nothing here: the architecture never lets either
model invent a fact (see `ARCHITECTURE.md`) — it only rephrases a
pre-verified note. The 1.5B model's extra reasoning capacity isn't
load-bearing for a task that's structurally "say this paragraph in
friendlier words," so the smaller, 3-5x faster model does the same job.

## AgriLens classifier alone

- `classify.py` on a real tomato Septoria leaf-spot photo: **680ms**,
  **99.997%** confidence, correct diagnosis — pure-numpy MobileNetV2
  forward pass, no GPU, no torch.

## Memory headroom (why model size is a real constraint here, not a nicety)

- `llama-server` alone (1.5B model loaded): ~1GB RSS.
- System free RAM with that server running: **~26-41MB truly free**
  (~1.6GB "available" counting reclaimable cache).
- This is the direct evidence against adding an embedding model + vector
  index + a multi-agent framework (LangGraph or similar) on top — there
  isn't RAM margin to spare for a second heavy process, and the actual
  retrieval task (one keyword match, one rephrase call) doesn't need one.

## Fleet Risk classifier (prototype, now running on-device)

Held-out-trip evaluation (44 training trips / 10 test trips, Kaggle
harsh-driving dataset, 54 trips total, ~33k rows):

| Stage | Metric | Result |
|---|---|---|
| 1 — event detector (binary) | accuracy | 70% |
| | recall / precision, "event" class | 57% / 49% |
| 2 — event-subtype classifier (6-way, event rows only) | accuracy | 53% |

Both models: RandomForest, 30 trees, depth 6 — small enough to port to
ESP32 firmware as plain C if/else logic later. Full report:
`vehicle-risk/model/train_report.txt` (generated by `train.py`).

**On-device replay, measured on the same Redmi 24116RNC1I phone:** a full
1,034-row trip replayed through both forests (pure-Python tree walk, no
numpy/sklearn) in **54ms** total — 246 elevated-risk moments flagged, 215
of them high-risk. Verified numerically identical to sklearn's own
`predict_proba` on this trip (max probability diff across all 1,034 rows:
0.000000). Confirmed working both as a web UI tab (`/fleet`) and as a
standalone terminal script (`replay_termux.py`), both with zero network
calls in the process.

## Now measured (previously listed as open)

- **End-to-end AgriLens/LearnLoop pipeline timing through `app.py`** (not
  just the isolated completion call): AgriLens 7.1-20.3s SLM time across
  6 real photos (classify stage 180-716ms separately); LearnLoop 38-55s
  across 6 back-to-back live questions. See `BATTLE_TEST_REPORT.md` for
  the full per-call breakdown — note this is measurably slower than the
  15.3s single-shot number above under sustained repeated use.
- **Battery/thermal impact of a sustained session**: flat. 35.0°C before
  a ~25-call stress battery (AgriLens + LearnLoop + Fleet Risk), 34.0°C
  after. No throttling signature.
- **Airplane-mode proof**: done with WiFi explicitly disabled (not just
  the airplane-mode toggle, which didn't propagate to the radio on this
  Android build) — a real LearnLoop query submitted through Chrome
  returned the correct answer in 55.5s with the plane icon visible and
  WiFi confirmed off the whole time. Screenshots in `BATTLE_TEST_REPORT.md`.
